## Root cause: Zernio SSE auth

The Zernio MCP endpoint (`https://mcp.zernio.com/mcp`) requires `Authorization: Bearer <token>`.

**Attempted approaches that failed:**
1. Spawning `mcp-remote` as stdio proxy — fails because `mcp-remote` tries OAuth discovery first and gets 404 from Zernio (Zernio doesn't support OAuth).
2. Direct SSE via `SSEClientTransport` with `eventSourceInit: { fetch: customFetch }` — fails because `SSEClientTransport` constructor **overrides** the `fetch` property with its own wrapper that only uses `this._authProvider` for auth.
3. Direct SSE via `requestInit: { headers }` — works for POST requests but the initial SSE GET connection uses `EventSource` which ignores `requestInit`.

**What needs to happen next:**
- Option A: Spawn `mcp-remote` correctly with `--header` flag and find a way to make it skip OAuth (maybe `--no-oauth` or similar flag exists).
- Option B: Use a lower-level SSE client that supports custom headers (e.g., raw `eventsource` package with `headers` in constructor, or write a lightweight stdio proxy that forwards JSON-RPC over SSE with Bearer auth).
- Option C: Connect to Zernio's REST API directly without MCP (if Zernio exposes a plain REST API).
